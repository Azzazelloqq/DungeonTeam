# Lifecycle, cancellation и ресурсы

## Правило владения

Кто создал объект, тот отвечает за его освобождение. Владелец обязан быть виден из кода: root, presenter, viewmodel или disposable-объект.

1. Root передаёт свой `CancellationToken` всем операциям, ограниченным его жизнью.
2. Presenter/ViewModel хранят подписки в `CompositeDisposable`.
3. Загрузивший Addressables-ресурс освобождает его через будущую инфраструктурную границу либо передаёт это владение выше явно.
4. При выгрузке сцены сначала отменяются операции/освобождаются feature-root, затем scene root, затем сама сцена.
5. `Dispose` должен быть идемпотентным; повторный вызов инициализации того же экземпляра запрещён.

## Дочерние узлы

Для child root, presenter или viewmodel владелец соблюдает один порядок:

1. Создать ребёнка с явными зависимостями.
2. Зарегистрировать его в единственном механизме владения, подходящем его lifetime.
3. Вызвать `Initialize` или `InitializeAsync` с токеном владельца.
4. При замене или уничтожении владельца освободить ребёнка ровно один раз.

Регистрация до инициализации гарантирует очистку, если инициализация завершится ошибкой. Не добавлять child одновременно в двух владельцев.

`CompositeDisposable` применять только для child, lifetime которого в точности равен lifetime parent-а и порядок освобождения не важен. Он не поддерживает удаление и освобождает элементы в порядке добавления. Для заменяемых list item/page children parent хранит явную коллекцию или поле, освобождает удалённый child и удаляет его из этой структуры; оставшиеся children освобождает первым действием в `OnDispose`.

Это обязательно для MVP: базовый `Presenter` освобождает свои View и Model до собственного `CompositeDisposable`. Child presenter, которому при очистке нужны parent View/Model или строгий порядок, освобождается явно в `OnDispose`, а не через terminal composite.

## Асинхронность

- В новом коде используется `UniTask`.
- `async void` запрещён, кроме Unity callback или строго изолированного editor command.
- Каждая операция принимает `CancellationToken`, если может пережить кадр.
- Ошибки не подавляются: root или use case определяет, логировать, повторять или показывать ошибку пользователю.
